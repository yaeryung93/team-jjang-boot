# 일정 시뮬레이션 확장 설계

현재 계산 기능과 가짜 성공확률 API는 없습니다. `simulation` 패키지만 계산 코드를 둘 위치로 예약했습니다.

## 현재 데이터 관계

- Project 1:N Member, Project 1:N Task
- Task N:1 Member (선택 담당자)
- Task 1:N TaskProgress (변경 이력)
- Project.deadline은 날짜만 저장합니다. 팀의 시간대/하루 종료 시각은 후속 설계 대상입니다.
- Task의 3점 추정은 처음 계획한 전체 작업시간입니다. 진행률은 시간 소비율이 아니므로 `예상시간 × (1 − 진행률)`을 잔여시간으로 단정하지 않습니다.

## 구현 순서

1. 프로젝트 내부 작업 의존관계를 추가하고 자기 참조·다른 프로젝트 참조·순환을 거부합니다. 위상정렬 가능한 DAG여야 합니다.
2. 진행 중 작업의 잔여 3점 추정, 완료 상태, 휴일/작업 가능 시간 및 담당자별 동시 수행 제약을 정합니다.
3. DB와 LLM을 참조하지 않는 순수 Java 계산기를 작성합니다. 입력은 작업 스냅샷·의존관계·마감·가용시간·반복수·난수 seed로 전달합니다.
4. 매 시행에서 삼각분포로 시간을 추출하고 의존관계와 인력 제약을 반영해 종료 시각을 계산합니다. 세 추정값이 같으면 고정 시간을 사용합니다.
5. 마감 내 종료 비율과 종료일 분위수를 반환합니다. 같은 입력/seed의 재현성, 체인/병렬 DAG, 인력 충돌, 모든 작업 완료, 불가능한 마감, 순환 및 잘못된 추정값을 테스트합니다.
6. 입력 스냅샷과 알고리즘 버전, seed, 반복수 및 결과를 함께 저장한 뒤 What-if와 위험도 이력으로 확장합니다.

LLM은 WBS/추정 초안을 제안하고 사용자가 확인합니다. 확률은 계산기가 산출합니다. 결과는 입력 가정에 따른 모델 추정치이며 실제 성공 확률로 보정된 값은 아닙니다. 일 단위 마감과 시간 단위 작업을 비교하려면 반드시 작업 달력을 먼저 정의해야 합니다.

초기에는 한 애플리케이션에서 동기 계산을 시작하고 실제 실행시간과 트래픽을 측정한 뒤 큐·별도 서버를 검토합니다.
